- 日付: 2026-10-26
- 状態: **実機検証完了。0.6.1-m6で初回評価、0.6.6-m6（プロンプトv7）で10ケース再評価。平均101語・80〜150語10/10・拒否0/10。最終人手評価を残す。**
- 対象: arrows Alpha（arm64-v8a / RAM 12GB / Android 16）
- ブランチ: `main`

## 1. 結論

M6の最初の縦切りを実装した。設定画面から約2.59GBのGemma 4 E2Bモデルを任意ダウンロードし、SHA-256検証後に端末内で日本語→英語PixAIプロンプトを生成できる。バックエンドは設定で「OpenRouter（クラウド）」と「ローカルLLM（端末内）」を切り替えられる。

クラウドを使わない場合でも、M5までの辞書＋ML Kit翻訳はそのまま動く。ローカルLLMのダウンロード失敗、読み込み失敗、生成拒否、日本語混入、空応答のいずれでも、オフライン結果を壊さずエラーを表示する設計にした。

実機では、ADB接続後に10ケースを実行して以下を確認した。

- 初回ロード（コールド）: **6.4秒**。ページキャッシュ後の再ロードは**0.5秒**。
- 生成: **12.8〜18.8秒、平均15.6秒**（出力語数に比例）。
- 機内モード: **生成成功**。
- 生成拒否: **0/10**（成人向け2件を含む）。
- 出力: **平均89.0語**。80〜150語は7/10、80語未満は3/10（77・79・71語）。
- 暫定品質: 意図4.15 / 自然さ4.25 / 構造4.70 / **総合4.37（5点満点）**。
- メモリ: アプリPSSは2回生成後**1.73GB**、10回生成後**1.95GB**。終了後は**193〜219MB**まで解放。ユーザーが以前見た「約9GB」は端末全体の使用量で、アプリ単体ではなかった。
- 発熱・バッテリー: 10回連続でも大きな変化なし。バッテリー温度36.9°C、SKIN 38.5°C、CPU 49.7°C。

プロンプトは0.6.1-m6で「翻訳ではなく展開」「6文構成」「90〜130語」「設定・光・画風を明示」に変更した。これにより単純入力の出力が67語→86語に伸びた。詳細は [`M6_LOCAL_EVAL.md`](M6_LOCAL_EVAL.md)。

0.6.6-m6（プロンプトv7）で短文3件と不自然な英語を再調整した。10ケース平均**101.0語**、80〜150語は**10/10**、拒否**0/10**、生成平均**30.3秒**。`in-color hair`と`smile mixed with ...`は解消した。残りはID24の87語、ID27の125語、ID30の黒髪補完。詳細は [`M6_PROMPT_V7.md`](M6_PROMPT_V7.md)。

## 2. 確定した技術選定

| 項目 | 決定 |
|---|---|
| 推論基盤 | LiteRT-LM Android `0.18.1`（2026-10-20公開の最新） |
| モデル | Gemma 4 E2B IT（LiteRT-LM版、CPU用 `.litertlm`） |
| モデルサイズ | 2,588,147,712 bytes（約2.59GB） |
| SHA-256 | `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c` |
| Hugging Face revision | `1caa527c1e88b55f046fcd8d2b4265606680663d`（固定） |
| ライセンス | Apache-2.0 |
| バックエンド | CPU / 4 threads（GPUは次段階） |
| コンテキスト | 4,096 tokens |
| 出力上限 | 768 tokens（95〜115語＋タグに十分な上限。暴走時の待ち時間を抑える） |
| サンプリング | topK 10 / topP 0.95 / temperature 0.3 / seed 42 |
| 思考トークン | 無効（`enableThinking = false`） |

LiteRT-LMは`latest.release`ではなく`0.18.1`に固定した。AARはarm64-v8aのJNIを約22MB含むため、APKはM5の約51MBから約79MB（decimal）に増えた。

### GPUを今回入れなかった理由

- arrows AlphaのMali-G615でLiteRT-LM GPUが動くか未確認。
- GPU版モデルは別ファイル（2,008,432,640 bytes）で、CPU版との差分検証が必要。
- まずCPUで「動く・落ちない・オフラインで使える」を確認する。
- GPU対応はM6.1で、GPU版モデルの追加ダウンロードまたはCPU失敗時のフォールバックとして実装する。

## 3. 実装したもの

### 3.1 モデル管理

`LocalModelManager.kt`

- `DownloadManager`でHugging FaceからWi-Fi限定ダウンロード。
- 保存先はアプリ専用外部領域:
  `/storage/emulated/0/Android/data/com.prompter.app/files/Download/models/gemma-4-E2B-it.litertlm`
- ストレージ権限は不要。アンインストールでモデルも削除される。
- ダウンロードIDをSharedPreferencesに保存し、アプリ再起動後も進捗を復元。
- 完了後にファイルサイズとSHA-256を検証。
- 不一致ならファイルを削除し、再ダウンロードを促す。
- 検証済みのサイズと更新時刻を保存し、毎回2.59GBを再ハッシュしない。
- モデル削除、ダウンロードキャンセル、手動検証に対応。
- RAM 8GB未満、空き容量不足、Wi-Fi以外の開始をブロックまたは保留。

### 3.2 推論

`LocalLlm.kt`

- `Engine`をActivity内で再利用。2回目以降の生成ではモデルを再ロードしない。
- `Engine.initialize()`と`Conversation.sendMessage()`はIOディスパッチャで実行。
- 1つのEngineにつき同時生成は1つに直列化。
- `Conversation`は生成ごとに作り直し、会話履歴の混入を防ぐ。
- 生成後に`Conversation.close()`、Activity破棄時に`Engine.close()`。
- 読み込み時間と生成時間をミリ秒で返し、UIに表示。

### 3.3 プロンプト

`LocalLlmPrompt`

- システムプロンプトで`Subject + Action + Scene + Mood + Style`を指定。
- v7: 6〜7文、95〜115語、各文16〜19語。設定・光・画風の展開を明示。
- Markdown禁止、日本語禁止、入力にない固有名詞・物体の追加禁止。
- 単純入力でも汎用的な背景・光・画風で展開するよう指示。
- 入力にある色・髪型・服・人数を保持し、色の推測と脱落を禁止。
- 2状態の表情は`a faint smile`に統一し、`mixed with`を禁止。
- 成人向け要素は入力にある場合に保持し、拒否・検閲しないよう指示。
- オフライン辞書タグと未変換日本語をユーザープロンプトに含める。
- パーサーは`smile mixed with ... expression`を`a faint smile`に置換し、
  `in the center of ... face`を削除する。詳細は
  [`M6_PROMPT_V7.md`](M6_PROMPT_V7.md)。
- 出力形式:

```
PROMPT_BEGIN
<English prompt>
PROMPT_END
TAGS: <comma-separated canonical Danbooru tags, max 20>
```

パーサーはマーカー欠落、`TAGS:`の次行、Markdownフェンス、角括弧付きタグを許容する。以下は失敗として扱い、オフライン結果を保持する。

- 空応答
- `<English prompt>`の未置換
- `I'm sorry` / `I cannot`などの拒否文
- 自然文への日本語混入
- タグ内の日本語（タグだけ除去）

### 3.4 UI

`SettingsScreen.kt`

- AIバックエンド選択（クラウド / ローカル）。
- ローカルモデルの状態表示:
  - 未ダウンロード
  - ダウンロード中（進捗%、GB表示）
  - 検証待ち
  - SHA-256検証中
  - 準備完了
  - エラー
- ダウンロード、キャンセル、検証、削除、エンジン解放。
- モデル名、サイズ、ライセンス、必要RAM、Wi-Fi限定の注意を表示。
- ローカル選択時はOpenRouterのAPIキー入力を不要にした。

`MainActivity.kt`

- 設定したバックエンドを保存し、起動時に復元。
- AIカードの文言・ボタンをバックエンドに合わせて切り替え。
- ローカルモデル未準備なら設定画面へ誘導。
- 生成結果はクラウドと同じ`AiPromptValidator`でタグ検証し、履歴・キャッシュにも保存。
- キャッシュキーは`local:gemma-4-E2B-v7`。プロンプト設計を変えたら番号を上げる。
- 生成失敗時は`aiError`を表示し、オフライン結果は変更しない。

### 6.1 インストール

```bash
adb install -r /storage/emulated/0/Download/Prompter/Prompter-0.6.6-m6-debug.apk
adb shell am force-stop com.prompter.app
```

### 6.2 モデルダウンロード

1. 設定 → AIバックエンド → ローカルLLM（端末内）。
2. 「モデルをダウンロード（約2.59GB）」をタップ。
3. Wi-Fi接続を確認。
4. 通知と設定画面の進捗が更新されること。
5. 完了後に「SHA-256検証中」→「準備完了」になること。
6. ファイルサイズを確認:

```bash
adb shell run-as com.prompter.app ls -l \
  /storage/emulated/0/Android/data/com.prompter.app/files/Download/models/
```

期待値: `2588147712` bytes。

### 6.3 生成

1. 例: 「長い黒髪の少女が青いドレスを着て、椅子に座っている」を変換。
2. 「ローカルLLMで整える」をタップ。
3. 初回の読み込み時間、生成時間、語数がAIカードに表示されること。
4. 出力が英語で、`PROMPT_BEGIN`などのマーカーが残っていないこと。
5. 80〜150語が目標。短文入力では70〜80語になることがある（実測: 71〜110語、平均89語）。
6. タグが辞書内のものだけになっていること。
7. もう一度実行し、2回目が読み込みなしで速くなること。出力語数が増えると生成時間も増える（実測12.8〜18.8秒）。
8. アプリを再起動し、モデルが「準備完了」のままで再ダウンロード不要なこと。

### 6.4 オフライン

1. 機内モードをON。
2. アプリを強制停止して再起動。
3. モデルが「準備完了」のままであること。
4. ローカルLLMで生成できること。
5. ML Kit翻訳モデルもダウンロード済みなら、辞書外の翻訳が動くこと。

### 6.5 品質・負荷

- 日本語シーン10〜20件で、意図・自然さ・構造を5段階評価。
- 成人向けタグを含む入力で、拒否されずタグが保持されるか。
- 複数キャラ入力で属性が混ざらないか。
- 初回ロード時間、生成時間、RAM、発熱、バッテリー消費を記録。

```bash
adb shell dumpsys meminfo com.prompter.app
adb logcat -d | grep -iE "litert|gemma|prompter" | tail -100
```

### 6.6 失敗時

- ダウンロード失敗: DownloadManagerの通知と設定画面のエラー理由を確認。
- SHA不一致: ファイルが削除され、再ダウンロードできること。
- 読み込み失敗: アプリが落ちず、オフライン結果が残ること。
- 生成拒否/日本語混入: エラー表示され、オフライン結果が残ること。
- OOM/クラッシュ: `adb logcat`と`dumpsys meminfo`を保存。

## 7. 既知の制約・リスク

| 制約 | 内容 | 次アクション |
|---|---|---|
| 外部保存のmmap | app-specific external上の2.59GBから実機で生成できたため、mmap/読み出しは成功 | 問題が出た場合のみ内部storageへコピー |
| 品質評価 | 10ケースの暫定評価は総合4.37/5（v2）。v7は個別修正を確認したが、5点評価の再採点は未実施 | 10〜20件でユーザーが確認 |
| 短文出力 | v7では80語未満0/10。ただし3/10が95語未満（87・92・93語） | 95語の下限を厳密にするか、現状を許容するか決定 |
| 汎用補完 | 入力にない服装・髪・キッチンなどを補完する場合がある。v7でもID30で黒髪を補完 | 意図を変える具体物を減らすようプロンプト調整 |
| 不自然な英語 | `in-color hair`と`smile mixed with ...`はv7で解消。ID21の`hair`重複、ID27のコンマ結合が残る | 必要ならサニタイザーの対象を追加 |
| メモリ増加 | 2回→10回でPSS 1.73GB→1.95GB | 20〜30回で安定性を確認 |
| 生成時間 | v7は26.8〜37.9秒、平均30.3秒。v2の15.6秒から悪化 | 速度優先なら語数を下げるかGPU版へ |
| CPUのみ | GPU版モデル/バックエンドは未実装 | M6.1でMali-G615を検証 |
| 2.59GB | Wi-Fi必須。ストレージを大きく使う | ダウンロード前に容量表示済み |
| 8GB RAM要件 | 8GB未満は開始不可 | 実機12GBなので問題なし |
| 初回ロード | コールド6.4秒 / ページキャッシュ後0.5秒 | 初回のみ進捗表示を検討 |
| バックグラウンド | 生成中にOSがkillする可能性 | 必要ならForeground Service化 |
| ストリーミングなし | 完了までスピナー。v7は平均30.3秒 | 必要なら`sendMessageAsync`へ |
| 拒否検出は簡易 | 多様な拒否文を完全には検出できない | 実機の失敗例を収集して追加 |
| 成人向け | 2/2で拒否なし・内容保持 | バリエーションを増やして確認 |
| E4B未対応 | 12GB向け高品質パックは未実装 | E2Bの品質次第で追加 |
| モデル更新 | revision固定のため自動更新しない | 更新時はSHAとサイズを更新 |

## 8. 次の作業

1. **ユーザーによる人手評価**を10〜20件で行い、意図・自然さ・構造を5段階で確定する。v2の暫定スコアは [`M6_LOCAL_EVAL.md`](M6_LOCAL_EVAL.md) の4.37/5、v7の結果は [`M6_PROMPT_V7.md`](M6_PROMPT_V7.md)。
2. **20〜30回連続生成**でPSSの増加が止まるか確認する。10回時点は1.95GB。
3. v7の残り（ID24の87語、ID27の125語、ID30の黒髪補完）を許容するか、追加調整するか決める。
4. 0.6.6-m6でも機内モード生成を再確認する。
5. ダウンロードが再現性なく失敗する場合のみ、`DownloadManager`の理由コードとHugging Faceのリダイレクトを確認し、必要なら独自のレジューム付きHTTPダウンロードに切り替える。
6. CPUで安定しているため、次はGPU版モデル（2.01GB）と`Backend.GPU()`を任意設定で追加する。Mali-G615で失敗したらCPUへフォールバック。
7. M6の最終Go/No-Go後、PixAI自然文の人手評価（`research/PIXAI_EVAL.md`）へ進む。
