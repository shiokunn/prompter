# キャラクター名の自動検出 実現可能性調査

- 調査日: 2026-10-30
- 対象: 情景入力からキャラクター名を自動で見つけられるか
- 結論: **候補提示は実装可能。ただし現状のDBと単純な部分一致で「自動確定」するのは危険。**
- コード変更: 2026-10-30 にデータ修正と候補検出器を実装（§10）。実機検証は未実施。

## 1. 結論

1. 現在の同梱DB（10作品・621人・1,550別名）を使えば、入力文に含まれる名前を高速に探すことはできる。
2. ただし2文字以下の名前や一般語と同名のキャラクターが多く、単純な部分一致では**通常の情景文の約半分で誤検出**する。
3. 3文字以上の正式名に限定し、英語は単語境界を必須にし、2文字名は作品名が近くにある場合だけ許可すると、今回の20文では誤検出0件まで下げられた。
4. その制限では132人（全体の約21%）が自動検出の対象外になる。また、DBは10作品のみなので `初音ミク` / `VOCALOID` などは検出できない。
5. したがって現実的なのは、**検出結果を「候補ブロック」として表示し、ユーザーのタップで確定する方式**。入力だけで勝手にキャラクターを確定しない。
6. 未知キャラクターや曖昧な一般語名は、端末内AI（Gemma 4 E2B）による抽出候補を任意ボタンで出す余地がある。ただし実機での精度・速度は未検証。

## 2. 現在の実装

- キャラクターモードは手動でONにし、名前を入力してDB候補を選択する方式。
  - `app/src/main/java/com/prompter/app/MainActivity.kt`
  - `app/src/main/java/com/prompter/app/CharacterPanel.kt`
- `CharacterDb.search()` はSQLiteの `instr(alias, query) > 0` で部分一致する。
  - 入力された検索語が別名に含まれるかを見る向きであり、情景文から名前を抜く処理ではない。
- 名前が確定すると `CharacterIdentity.prefix()` で英語名と作品名をプロンプト先頭に付ける。
- 自動検出の処理は現状存在しない。作品名・英語名の手入力欄は直近のUI整理で削除済み。

## 3. DBの実測

`app/src/main/assets/characterdb.sqlite` を直接集計した。

| 項目 | 値 |
|---|---:|
| 作品数 | 10 |
| キャラクター数 | 621 |
| 別名行数 | 1,550 |
| 日本語正式名が2文字 | 121人 |
| 日本語正式名が2文字以下 | 132人 |
| 日本語正式名が3文字以上 | 489人 |
| 同じ別名文字列が複数キャラクターに紐づく | 67文字列 |
| 短い別名が別キャラクターの長い別名に含まれる | 136組 |

### 3.1 データ側の問題

- 台帳の注記が別名として混入している。
  - `二次資料。うまる`（土間埋）
  - `二次資料。ぼんば`（本場猛）
  - 原因: `tools/build_character_db.py` の別名抽出が `note.split("。")[0]` を使っており、「二次資料。」まで別名に含めるため。
- 1文字の英語別名 `D`, `K` が存在する。英語文中のほぼすべての文に誤一致する。
- `銀狼LV.999`（base）と `銀狼 LV.999`（variant）が正規化後に同一になり、最長一致でも2件残る。
- 作品をまたぐ同名がある。
  - `アリス`: 原神 / ゼンレスゾーンゼロ / NIKKE
  - `ダリア`: 崩壊：スターレイル / 原神
  - `ルーシー`: ゼンレスゾーンゼロ / 鳴潮
- 2文字以下の一般語・人名が多数ある。
  - `空`, `刃`, `影`, `花火`, `胡桃`, `北斗`, `甘雨`, `白雪`, `白露`, `姫子`, `蛍`, `少女` など

## 4. 検証方法

手作業で用意した汎用情景文20文（日本語）と23文（英語）に対し、DBの別名を部分一致させた。日本語は最長一致を優先し、長い別名に含まれる短い別名を除外した。英語は正規化後の単純部分一致と、英単語境界を要求する方式を比較した。

これは大規模ベンチマークではなく、誤検出の傾向を見るための小規模プローブである。

## 5. 結果

### 5.1 日本語の汎用情景20文

| 条件 | 別名が一致した文 | 主な誤検出 |
|---|---:|---|
| 1文字以上 | 10/20 | `少女`（6文）、`空`、`花火`、`ルカ`、`照`、`カブ` |
| 2文字以上 | 8/20 | `少女`（6文）、`花火`、`ルカ`、`カブ` |
| 3文字以上 | 0/20 | なし |

3文字以上でも一般語・人名と同名のキャラクターは残る。`アリス`（一般名、3作品で同名）、`ダリア`（花名、2作品で同名）、`シード`（seed）、`スター`（star）などで、今回の20文に含まれなかったため0件だっただけであり、誤検出がゼロになるわけではない。`アリスは不思議の国にいる` のような文では3作品の候補が同時に出る。

代表例:

- `長い黒髪の少女が...` → 原神の `少女`（Damselette）
- `青空の下...` → 原神の `空`（Aether）
- `花火を見上げるカップル` → `花火`（Sparkle）と、`カップル` 中の `ルカ`
- `月明かりに照らされた...` → `照`
- `夜空に浮かぶ...` → `浮かぶ` 中の `カブ`
- `桜の木の下で弁当を食べる学生` → `食べる` 中の `ベル`
- `ヴェスナが...` → 名前末尾の `な` と助詞 `が` が `ナガ` に一致
- `NIKKEのアリス` → `NIKKE` 中の `K` と、`の` + `アリス` の先頭が `ノア` に一致

アプリ内蔵のサンプル文3つのうち、`少女` を含む2つが該当する。

### 5.2 英語の汎用情景23文

| 条件 | 誤検出した文 | 主な誤検出 |
|---|---:|---|
| 単純部分一致 | 20/23 | `D`, `K`, `Sin`, `Star`, `Rapi`, `Anis` |
| 英単語境界 + 3文字以上 | 3/23 | `seed`（Seed） |
| 英単語境界 + 5文字以上 | 0/23 | なし（ただし3〜4文字名を検出できない） |

英語は `D`/`K` のような1文字別名の影響が大きく、単語境界なしでは使い物にならない。単語境界を入れても `seed` のような一般語名は残る。

### 5.3 DB内の名前をそのまま文に入れた場合

621人それぞれについて `正式名 + は微笑んでいる` を作り、最長一致で判定した。

| 結果 | 人数 |
|---|---:|
| 一意に検出 | 607 |
| 同名・別形態などで曖昧 | 14 |
| 検出漏れ | 0 |

これは「名前が正しく書かれている」前提の上限値であり、自然文での精度ではない。曖昧14人は `アリス`、`ダリア`、`銀狼LV.999`、`ルーシー`、`アリア` などの重複・別形態による。区切りを `が` にすると名前末尾と助詞が別名に一致し、曖昧数が29まで増える（例: `ヴェスナ` + `が` が `ナガ` に一致）。

### 5.4 DBのカバレッジ

| 入力例 | 検出 |
|---|---|
| `初音ミク` | 0件 |
| `ミク` | 0件 |
| `VOCALOID` | 0件 |
| `五条悟` | 0件 |
| `ルフィ` | 該当なし（`シルフィンフォード` の部分一致のみ） |
| `ナルト` | 該当なし（`レーナルト` の部分一致のみ） |

同梱DBは10作品のみのため、**ユーザーが例に挙げた初音ミク／VOCALOIDは自動検出できない**。DB外の名前を扱うには、DB拡張かAI抽出＋手動確認が必要。

## 6. 方式比較

| 方式 | 精度 | 速度 | オフライン | 未知キャラ | 実装コスト | 評価 |
|---|---|---|---|---|---|---|
| 現状DBの部分一致 | 低（短い名前で誤検出多） | 高速 | ○ | × | 小 | 単独では不可 |
| 境界・安全別名・作品文脈で制限 | 中〜高 | 高速 | ○ | × | 中 | **候補提示に推奨** |
| 端末内AI（Gemma 4 E2B）で抽出 | 未検証 | 低速（従来の生成は約39秒/230語） | ○ | △（名前は出せるが照合先がない） | 中 | 任意の補助に向く |
| クラウドLLMで抽出 | 高（モデル次第） | 高速 | × | ○ | 中 | APIキー利用時のみ。送信同意が必要 |
| ML Kit Entity Extraction | 対象外 | — | ○ | — | — | 日本語対応だが住所・日時・URL等のみ。人名は取れない |
| 日本語NER（GiNZA/BERT等） | ドメイン適応が必要 | 中 | △ | △ | 大 | 現状のアプリには過大 |
| 翻訳→Danbooru英語タグ照合 | 中（翻訳依存） | 中 | ○ | ○（40,931タグ） | 大 | 将来候補。翻訳誤りと同名問題が残る |
| 外部キャラクターAPI | — | 高速 | × | ○ | 中 | 名前が分かった後の照会向き。検出自体は不可 |

補足:

- ML Kit Entity Extraction は日本語に対応するが、抽出できるのは住所・日時・メール・電話・URL・金額などで、人名・キャラクター名のエンティティは提供していない。
- 日本語NERの研究では、アニメ・ゲームのキャラクター名はドメイン固有で、一般の形態素解析だけでは分割・認識が難しいことが報告されている。
- 端末内AIは2.6GBのモデルを端末にダウンロード済みで、追加ダウンロードなしで試せる。ただし本アプリのプロンプトは画像プロンプト生成用であり、名前抽出タスクでの精度・速度は別途評価が必要。
- クラウドLLMはAPIキー設定時のみ。情景文を外部送信するため、明示的な同意と「検出だけ外部送信する」旨の表示が必要。

## 7. 推奨する設計

### 7.1 UX

- キャラクターモードがONのとき、情景入力の下（または名前欄の下）に **「情景から見つかった候補」** をブロック表示する。
- 候補はタップで選択するだけ。**自動で名前欄・プロンプトへ反映しない。**
- 一意な正式名が1件だけ見つかった場合も、候補ブロック1件を出すに留める。
- 曖昧な場合は作品名付きで2〜4件を出す。候補なしなら何も出さない。
- 小さな説明文は追加しない。既存の候補ブロックUIを再利用する。

### 7.2 検出ロジック（推奨）

1. 入力文をNFKCで正規化する。ただし**自動検出ではカタカナ→ひらがな変換をしない**（`ノア` が `の+アリス` に一致するのを防ぐ）。
2. 別名を最長一致で探す。長い別名に含まれる短い別名は捨てる。
3. 1文字の別名は自動検出に使わない。
4. 英語別名は前後が英字でないことを必須にし、3文字以上に限定する。
5. 日本語2文字以下の別名は、入力文に同じ作品名がある場合だけ許可する。
   - 例: `原神の胡桃` はOK、`胡桃を食べる` は候補にしない。
6. 作品名がある場合は、その作品のキャラクターを優先し、他作品の同名は落とす。
7. それでも残る同名（`アリス` など）は自動決定せず、複数候補として表示する。
8. 候補のスコアは「一致した別名の長さ、正式名か別名か、作品名の一致、別形態か」で決める。

### 7.3 未知キャラクター

現状のUIはDB候補を選ぶ以外に英語名を確定する手段がない。自動検出でDB外の名前を見つけても、そのままでは行き止まりになる。選択肢は次のいずれか。

- DBを拡張する（日本語別名の整備と再配布条件の確認が必要）。
- ローカルAIで英語名候補を出し、ユーザーが確認する。
- 英語名の手入力欄を限定的に復活させる。

いずれも製品判断が必要。自動検出だけを先に入れると、未知キャラクターで「候補は出るが選べない」状態になる。

### 7.4 データ修正（実装前）

1. `tools/build_character_db.py` の別名抽出を修正し、`二次資料。うまる` のような注記混入をなくす。
2. 1文字の英語別名 `D`, `K` を検出対象から除外する（検索用には残してよい）。
3. `銀狼LV.999` と `銀狼 LV.999` の重複を解消する。
4. 別名に `detect_safe` / `ambiguous` のような属性を追加し、検索用別名と自動候補用別名を分ける。
5. 作品をまたぐ同名（アリス、ダリア、ルーシー）に作品IDを持たせ、作品名が入力にある場合の絞り込みを可能にする。

## 10. 実装状況（2026-10-30）

### 10.1 データ修正

- `tools/build_character_db.py`
  - 「は別名」の前の最後の文だけを別名として採用し、`二次資料。うまる` のような注記混入を削除した。
  - 別名に `detect_tier` を追加した。
    - `0`: 検出に使わない（1文字、読み、1文字の英字別名）
    - `1`: 同じ作品名が情景にある場合だけ候補にする（2文字）
    - `2`: 候補にしてよい（3文字以上）
  - 1文字の `D` / `K` は検索用には残し、検出対象から除外した。
  - 作品をまたぐ同名は削除せず、既存の `series_id` と作品名検出で絞り込む。
  - `銀狼LV.999` と `銀狼 LV.999` は、元台帳が「別形態レコード。別名統合禁止」としているため統合せず、別候補として残す。UIでは別形態バッジで区別する。

### 10.2 検出器

- `app/src/main/java/com/prompter/app/CharacterMentionDetector.kt`
  - NFKC + 小文字化。日本語はカタカナ→ひらがな変換をせず、空白・区切りだけ除去する。
  - 1文字は対象外。2文字は作品名がある場合だけ候補。3文字以上は候補。
  - 英語は前後が英字でないことを必須にする。
  - 最長一致を優先し、正式名がある場合は別形態の短い別名を落とす。
  - 作品名が情景にある場合は、その作品のキャラクターだけに絞る。
  - 同名が残る場合は自動決定せず、最大8件の候補を返す。
- `app/src/main/java/com/prompter/app/MainActivity.kt`
  - キャラクターモードON、名前欄が空、未確定のときだけ情景から検出する。
  - 180msのデバウンス後にIOスレッドで実行する。
- `app/src/main/java/com/prompter/app/CharacterPanel.kt`
  - 名前欄の下に「情景の候補」を既存の候補ブロックで表示する。
  - 候補はタップするまで名前・作品・英語名に反映しない。
- `app/src/main/java/com/prompter/app/CharacterNames.kt`
  - `worksIn()` を追加し、作品名の検出を検出器と共有する。
